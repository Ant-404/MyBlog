# 注册用户、评论保障与 QQ 邮箱配置

新增普通用户账号，和现有管理员账号分开。游客可以以“匿名用户”发表评论、回复和留言墙便签，审核通过后公开；注册用户验证邮箱并登录后，文章评论先展示再审核。留言墙便签仍先审核后公开，举报需注册用户。历史游客评论保留，不按昵称自动绑定账号。

评论继续使用 PENDING / APPROVED / REJECTED 三种状态：PENDING 且 member_id 非空时公开，为空时隐藏；APPROVED 公开，REJECTED 隐藏。后台待审核列表标明当前是否展示。重新审核恢复为 PENDING，并按同一规则决定可见性。已有注册用户待审核评论也适用新规则；本次无需新增 SQL。

昵称和用户编号由服务端决定，公开游客名称统一为“匿名用户”。匿名写入保留 CSRF、来源限流和诱捕字段；注册用户额外按账号限流，禁言或失效会话不会降级为匿名提交。公开回复产生站内通知，被拒绝后隐藏通知；匿名回复通过后才产生通知。

## 启用步骤

1. 停止后端并备份数据库，在 MySQL 客户端手动执行整个 `database/MyBlog.sql`。V11 增加会员、一次性验证令牌、通知、举报、留言墙，并兼容添加评论的 member_id、parent_id 和会员索引。没有自动执行本机 MySQL 升级。

   V12 将留言墙的 member_id 改为可空，以持久化匿名便签；已执行 V11 的数据库也需重新执行唯一 SQL 文件，再启动后端。现有注册留言与关联保留。游客可直接填写“写张便签”，无需邮箱或昵称；匿名便签仅由管理员管理，注册用户仍可在个人中心管理自己的便签。留言墙每个来源十分钟最多 3 次提交，注册用户另按账号限流，保留 CSRF 和 website 诱捕字段。

   编辑区默认收起，点击“写留言”展开；临时收起保留当前文字，提交成功自动收起。“预览便签”会在提交前展示当前文字、作者和所选颜色，纯文字处理，不会发布。提交失败会保留输入。若运行中的旧后端仍要求登录，即使前端已热更新，游客提交仍会失败；需完成 V12 并重启实际运行的后端。页脚“管理后台”在新标签页或窗口打开，保留当前博客页面。
2. 在 QQ 邮箱设置中开启 SMTP 服务，生成授权码。授权码不是 QQ 登录密码，不要写入源码、聊天或 Git。
3. 在本机 `backend/.env` 填写下列配置。已补齐缺失字段，默认关闭发信，不覆盖原有数据库连接或凭据。

```properties
MEMBER_MAIL_ENABLED=true
SMTP_HOST=smtp.qq.com
SMTP_PORT=465
SMTP_AUTH=true
SMTP_SSL=true
SMTP_STARTTLS=false
SMTP_USERNAME=你的完整QQ邮箱地址
SMTP_PASSWORD=QQ邮箱生成的SMTP授权码
```

发件人默认使用 SMTP_USERNAME；如设置 SMTP_FROM，必须填写该 SMTP 账号允许发送的地址。其他 SMTP 服务可以改用其对应参数。

4. 重新启动后端。在“后台 → 站点设置”将公开站点地址设为实际访问的前端根地址。本机通常为 `http://127.0.0.1:5173`，线上填写真实 HTTPS 域名。验证邮件使用这个地址，不从访客传来的 Host 或 Referer 拼接链接。
5. 前端开发服务自动更新，正式部署需重新构建并发布前端。点击右上角用户图标，进入注册流程，确认自己能收到 QQ 发出的验证邮件。

本轮只验证了本机隔离 SMTP 收件服务的真实邮件投递，没有连接你的 QQ SMTP 服务发送邮件。未配置或未启用时，页面明确显示邮箱服务尚未启用，注册与找回密码不可用，已有账号仍可登录。邮件投递失败不会留下可消费的新令牌。

## 用户可以做什么

- `/account`：邮箱验证注册、登录、找回密码、修改资料和密码、查看/删除自己的评论及便签、阅读回复通知、注销。
- `/people/:id`：公开昵称、头像、简介和固定账号编号；不公开邮箱、账号状态、密码或登录信息。评论中的用户名可打开这页。
- 评论：服务器从当前账号读取昵称和编号，忽略客户端提供的 author；支持回复、举报，回复审核通过后通知原评论作者。自己回复自己不通知。
- `/guestbook`：填写最多 500 字的纯文字便签，选择四种颜色。审核后公开，作者可以删除；待审核便签可以在个人中心删除。

昵称允许重复，通过固定的 `#账号编号` 区分。注册代表验证了邮箱控制权，不代表实名验证。

新账号没有管理权限。普通用户与管理员使用同一站点的会话 Cookie；同一浏览器登录另一种账号会替换当前身份。需要同时操作时使用不同浏览器或独立浏览器配置。

评论草稿仍只保存在本标签页的 sessionStorage，按账号和文章隔离，不再自动读取旧游客草稿；提交成功立即移除当前草稿。密码不写入浏览器存储。

## 后台管理

`/admin/members` 的“用户与社区”提供三部分：

| 部分 | 操作 |
| --- | --- |
| 用户 | 按昵称/邮箱搜索，正常、禁言、封禁状态切换 |
| 评论举报 | 查看举报原因和被举报内容，前往评论审核，标记已处理 |
| 留言墙审核 | 通过、拒绝、永久删除便签 |

禁言用户可以登录、管理资料和删除自己的内容，不能发布评论、回复、便签或举报。封禁用户不能登录。状态变化使旧登录失效，需要重新登录。账号状态、资料、评论和便签的修改使用版本校验，冲突不会覆盖新数据。

注销需再次输入密码并确认。清除邮箱、密码哈希、头像与简介，删除本人的通知、举报记录及便签；保留历史评论并匿名显示“已注销用户”。用户可以先删除自己的评论再注销。保留数据库内部编号以维护评论关联，注销不等于删除站点备份。

## 已实施的保护

- BCrypt 保存密码；至少 10 字符，按 UTF-8 最多 72 字节。注册和重置均需验证邮箱，改密需验证当前密码。
- 使用 HttpOnly、SameSite=Lax 的服务端会话和 CSRF 校验，登录轮换会话 ID 与 CSRF 令牌。改密、重置、封禁和注销通过 session_version 使旧会话失效。
- 邮件令牌使用 32 字节安全随机数，数据库只存 SHA-256，30 分钟有效、一次性消费，限定邮箱与用途。申请新链接会替换该邮箱同用途的旧链接。
- 注册和找回邮件采用统一提示，不直接告知邮箱是否已注册；页面读取验证链接后从地址栏移除令牌。不要转发验证邮件；反向代理也应避免记录 `/account` 的敏感查询参数。
- 每个 IP 十分钟最多申请 5 次邮件、每个邮箱 3 次，并有 60 秒重复发送间隔。登录每 IP 十分钟 20 次、每邮箱 10 次；评论每 IP 和账号十分钟最多 5 条；便签每账号 3 条；举报每账号 5 次。
- 以上限流为当前单实例内存状态，重启会清空；多实例部署需共享会话和分布式限流。部署沿用 HTTPS、SESSION_COOKIE_SECURE=true 和可信反向代理配置。
- 评论与便签按纯文字渲染；头像地址校验；管理接口与用户接口分别校验角色，个人内容操作验证所有权。邮箱仅本人和管理员可见。

## 验证与代码

后端入口：`backend/src/main/java/com/myblog/member/`。浏览器入口：`frontend/src/pages/AccountPage.tsx`、`MemberProfilePage.tsx`、`GuestbookPage.tsx`，后台为 `pages/admin/AdminMembersPage.tsx`。邮件配置模板为 `backend/.env.example`。

`MemberIntegrationTest` 验证令牌、真实会话、权限隔离、重置/改密失效、评论身份与所有权、通知、举报、禁言封禁、注销、公开资料及留言墙审核；浏览器测试 `tests/members.spec.ts` 使用仅监听本机的 SMTP 测试服务实际接收验证邮件。测试收件接口只存在于测试进程，应用不提供读取验证邮件或令牌的接口。
