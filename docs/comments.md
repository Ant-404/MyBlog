# 访客评论

## 预览与头像

点击预览在工具栏下方展开独立区域，输入框保持可见，编辑时实时更新，再次点击收起。颜文字面板提供 24 个文字表情，不使用 emoji。输入区和评论列表头像从 `frontend/public/images/user` 随机分配，同一页面内编辑或刷新列表时保持不变；目录图片在开发时自动发现，正式部署新增图片后需重新构建前端。

文章底部直接填写昵称、邮箱和可选网址，无需注册、登录或验证码。邮箱不会公开，管理员仅能看到填写值，不代表已验证邮箱控制权。评论提交后立即公开，历史评论统一展示，管理员可删除不合适的内容。

评论框提供 500 字计数、颜文字、本地照片或图片链接插入、Markdown 预览、回复与刷新。点击图片按钮可选择本地照片，原图最大 20MB，浏览器将长边缩至最多 1600px 并转换为 JPEG 后上传，成功后插入本站图片地址并展开预览；上传失败保留文字，也可重选同一张照片。仍支持 HTTP/HTTPS 图片链接。链接、图片与文本经过同一份清理规则后用于预览和公开展示。外链在新标签页打开并标记 ugc/nofollow；图片不发送 Referer。

照片接口 `/api/v1/comments/images` 允许访客带 CSRF 上传，每个来源地址十分钟最多 10 次，后端按真实图片内容校验（最大 5MB、2000 万像素）并重新编码，图片存入原媒体目录，后台媒体库可管理；评论正在引用的照片禁止直接删除，先删除相应评论或移除引用。上传后尚未发送的照片也保留在媒体库，便于管理员清理。

留言墙顶部显示最多九张彩色便签，可切换“最新九张”或“随机九张”，随机模式从全部留言抽取，不受分页限制，可点击“换一组”。便签支持查看全文、Esc 关闭并恢复焦点；顶部“写张便签”可直接跳到编辑器。下方保留全部留言列表、分页和后台管理，发布后顶部便签墙同步刷新；少于九条时展示实际条数，不填充示例留言。

草稿按文章保存在本标签页的 sessionStorage，包含未提交的昵称、邮箱、网址和正文。提交失败保留输入，成功清除正文草稿。昵称与邮箱只是评论信息，不创建账号，也不会向该邮箱发送验证码或通知。

后台 `/admin/comments` 管理全部评论，`/admin/guestbook` 管理全部便签，均可查看和删除，不提供审核、状态筛选或待审核统计。管理员登录保留。站点导航不再提供访客账号入口，旧 `/account` 与 `/people/:id` 返回 404。旧会员数据表保留以维护历史内容引用；没有删除历史评论或会员数据，也没有新增外部评论服务依赖。

## 部署

执行 `database/MyBlog.sql`，幂等补齐 comments.guest_email、comments.guest_url，再重启后端。新建数据库自动包含这两个字段。构建并发布前端。SMTP 已与访客认证解耦，不再需要 MEMBER_MAIL_ENABLED 等会员发信配置；本机已有 SMTP 凭据不作删除。

历史数据库的 status 列保留兼容，但查询不再按状态过滤，新记录显式写入 APPROVED；无需迁移或删除历史数据。

## 验证

后端 `CommunityIntegrationTest` 检查昵称/邮箱/网址和字数校验、邮箱公开隔离、即时公开与管理员删除、跨文章回复限制、CSRF、限流、防诱捕、九张便签抽取以及已移除的会员入口；`MediaIntegrationTest` 覆盖访客照片上传、格式校验、CSRF、限流及评论图片引用保护。浏览器 `tests/comments.spec.ts` 检查即时发布与后台删除、预览清理、表情与图片链接、草稿恢复、失败重试及手机端和暗色模式；`tests/comment-photo.spec.ts` 检查本地照片缩放上传与失败保留内容；`tests/guestbook-wall.spec.ts` 检查便签切换、全文查看、错误重试和响应式布局。便签发布流程由 `tests/guestbook.spec.ts` 覆盖。
